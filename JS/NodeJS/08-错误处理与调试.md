# 错误处理与调试

## 错误类型

### 内置错误类型

```javascript
Error          // 通用错误
SyntaxError    // 语法错误
TypeError      // 类型错误
ReferenceError // 引用未定义变量
RangeError     // 数值超出范围
URIError       // URI 处理错误
EvalError      // eval 错误（已弃用）
// Node.js 特有的
AssertionError // assert 断言失败
SystemError    // 系统级错误（EACCES, ENOENT 等）
```

### 系统错误码

```javascript
const fs = require('fs')

try {
  fs.readFileSync('/nonexistent')
} catch (err) {
  console.log(err.code)   // 'ENOENT'
  console.log(err.syscall) // 'open'
  console.log(err.path)    // '/nonexistent'
}
```

常见系统错误码：

| 错误码 | 含义 |
|--------|------|
| `ENOENT` | 文件/目录不存在 |
| `EACCES` | 权限不足 |
| `EADDRINUSE` | 端口已被占用 |
| `ECONNREFUSED` | 连接被拒绝 |
| `ETIMEDOUT` | 连接超时 |
| `EEXIST` | 文件已存在 |
| `ENOTDIR` | 不是目录 |
| `EISDIR` | 是目录（期望是文件） |

## 错误处理模式

### try/catch

同步代码和 async/await 中使用：

```javascript
// 同步
try {
  JSON.parse('invalid json')
} catch (err) {
  if (err instanceof SyntaxError) {
    console.error('JSON 解析失败')
  } else {
    throw err // 重新抛出未知错误
  }
} finally {
  console.log('总会执行')
}

// async/await
async function readFile() {
  try {
    const data = await fs.promises.readFile('file.txt')
    return data
  } catch (err) {
    console.error('读取失败:', err.message)
    throw err // 或返回默认值
  }
}
```

### 回调中的错误处理

```javascript
fs.readFile('file.txt', (err, data) => {
  // error-first 风格
  if (err) {
    console.error(err)
    return
  }
  // 处理 data
})
```

### Promise 错误处理

```javascript
doSomething()
  .then(result => doNext(result))
  .catch(err => {
    // 处理链中任何阶段的错误
    console.error(err)
    // 返回默认值继续链
    return defaultValue
  })
  .then(data => console.log(data))
  .finally(() => cleanup())
```

### EventEmitter 错误事件

```javascript
const stream = fs.createReadStream('nonexistent')
stream.on('error', err => {
  console.error('流错误:', err.message)
})
```

## 全局未捕获错误

```javascript
// 未捕获的异常
process.on('uncaughtException', err => {
  console.error('未捕获异常:', err)
  // 记录日志后优雅退出
  process.exit(1)
})

// 未处理的 Promise 拒绝
process.on('unhandledRejection', (reason, promise) => {
  console.error('未处理的 Promise 拒绝:', reason)
})
```

**注意：** `uncaughtException` 是最后防线，不应作为常规错误处理手段。最佳实践是在退出前清理资源。

## 自定义错误

```javascript
class ValidationError extends Error {
  constructor(message, field) {
    super(message)
    this.name = 'ValidationError'
    this.field = field
  }
}

class DatabaseError extends Error {
  constructor(message, query) {
    super(message)
    this.name = 'DatabaseError'
    this.query = query
    this.timestamp = Date.now()
  }
}

// 使用
throw new ValidationError('用户名不能为空', 'username')
throw new DatabaseError('连接超时', 'SELECT * FROM users')
```

### 错误包装

```javascript
function parseJSON(str) {
  try {
    return JSON.parse(str)
  } catch (err) {
    // 包装原始错误，保留调用栈
    throw new Error(`JSON 解析失败: ${err.message}`)
    // 或保留原始错误
    const wrapped = new Error('JSON 解析失败')
    wrapped.cause = err
    throw wrapped
  }
}
```

## 调试技巧

### 命令行调试

```bash
# 检查语法
node --check app.js

# 启用 inspector（Chrome DevTools）
node --inspect app.js
node --inspect-brk app.js  # 在第一行暂停

# 打印事件循环观察
node --trace-warnings app.js
node --trace-uncaught app.js

# 性能分析
node --prof app.js
node --prof-process isolate-*.log > processed.txt
```

### 使用调试器

```bash
# 内置调试器
node inspect app.js

# VS Code 调试 - 在 .vscode/launch.json
# {
#   "type": "node",
#   "request": "launch",
#   "name": "启动程序",
#   "program": "${workspaceFolder}/app.js"
# }
```

### console 调试技巧

```javascript
console.log('%o', obj)           // 展开对象
console.dir(obj, { depth: 3 })   // 指定深度
console.trace('trace')           // 打印调用栈
console.assert(condition, msg)   // 条件断言

// 计时
console.time('timer')
// ...
console.timeLog('timer', 'step1') // 中间计时
console.timeEnd('timer')

// 分组
console.group('Group')
console.log('item 1')
console.groupEnd()

// 计数
console.count('click')
console.count('click')
console.countReset('click')
```

### Node.js 调试日志

```javascript
// 使用 util.debuglog
const util = require('util')
const debug = util.debuglog('myapp')

debug('调试信息') // 仅 NODE_DEBUG=myapp 时输出

// 运行: NODE_DEBUG=myapp node app.js
```

### 内存泄漏排查

```bash
# 生成堆快照
node --heapsnapshot-signal=SIGUSR2 app.js
kill -USR2 <pid>

# 或代码中生成
const { writeHeapSnapshot } = require('v8')
writeHeapSnapshot()

# Chrome DevTools 中加载 .heapsnapshot 文件分析
```

### 性能分析

```bash
# 内置 prof
node --prof app.js
node --prof-process isolate*.log > profile.txt

# 火焰图（需要 Linux perf）
perf record -F 99 -p <pid> -g --sleep 10
perf script > out.perf

# 使用 clinic.js
npx clinic doctor -- node app.js
npx clinic flame -- node app.js
npx clinic heapprofiler -- node app.js
```
