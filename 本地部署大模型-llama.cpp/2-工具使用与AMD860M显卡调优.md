# llama.cpp 全功能使用详解（适配Windows AMD Vulkan环境）
llama.cpp 是一款纯C/C++实现的轻量级高性能大模型本地推理框架，核心优势是跨平台、极低的资源占用、全硬件加速支持，仅支持**GGUF格式**模型，是本地部署开源大模型的首选工具。本文档兼顾通用用法与你的AMD Radeon 860M核显专属优化，覆盖从入门到进阶的全场景用法。

---

## 一、核心前置：核心组件与模型规范

### 1. 核心可执行文件说明
Windows预编译包解压后，核心功能文件如下，所有功能均围绕这些文件展开：
| 文件名 | 核心功能 | 高频使用场景 |
|--------|----------|--------------|
| `llama-cli.exe` | 命令行推理/对话核心工具 | 本地交互式对话、单次文本生成、prompt测试 |
| `llama-server.exe` | 内置HTTP服务，**100%兼容OpenAI API格式** | 搭建本地API服务、对接第三方应用、Web界面聊天 |
| `llama-gguf.exe` | GGUF模型全生命周期处理工具 | 查看模型信息、模型量化、拆分/合并、LoRA融合 |
| `llama-bench.exe` | 硬件性能基准测试工具 | 测试不同模型的生成速度、显存/内存占用、参数优化 |
| `llama-embedding.exe` | 文本嵌入生成工具 | 本地RAG检索、知识库搭建、文本相似度计算 |
| `llama-tokenize.exe` | 分词工具 | 查看prompt的token数量、分词结果、费用预估 |

### 2. 模型规范与选择指南
量化是平衡模型效果、显存占用、生成速度的核心，不同量化等级的适配场景如下：
| 量化等级 | 7B模型显存占用 | 效果损失 | 推荐场景 |
|----------|----------------|----------|----------|
| `Q2_K` | ~3.2GB | 中等 | 极限低显存、极速响应、简单问答 |
| `Q4_K_M` | ~5.5GB | 极小（黄金标准） | **首选**，日常对话、通用任务、速度与效果完美平衡 |
| `Q5_K_M` | ~6.8GB | 几乎无 | 追求更好的推理效果、复杂逻辑任务 |
| `Q8_0` | ~10GB | 可忽略 | 高精度推理、专业场景 |
| `FP16` | ~13GB | 原生效果 | 不推荐，仅高端独显适用 |

## 二、核心场景全用法详解

### 场景1：命令行交互式对话（llama-cli）
这是最基础、最常用的本地对话方式，分为基础交互、单次生成、高级定制三个层级。

#### （1）基础交互式对话（直接复制可用，适配860M核显）

```powershell
# 进入llama.cpp解压目录（示例：D:\llama.cpp）
cd D:\llama.cpp

# 完整交互式对话启动命令
.\llama-cli.exe `
  -m models/qwen2.5-7b-instruct.Q4_K_M.gguf `
  -ngl 99 `
  --device Vulkan0 `
  -t 8 `
  --ctx-size 4096 `
  --temp 0.7 `
  --flash-attn `
  --chat-template auto `
  --color `
  -i
```
核心参数说明：
- `-i`：开启交互式对话模式，输入内容后按回车即可生成回复
- `--chat-template auto`：自动适配模型的对话模板，解决输出乱码、效果差的核心问题
- `--color`：区分用户输入与模型输出，提升可读性
- 其余GPU加速、线程参数已针对你的860M核显优化，无需修改

#### （2）单次文本生成（非交互式）
适合批量生成文案、脚本、报告等，无需人工交互，执行完成后自动退出：
```powershell
.\llama-cli.exe `
  -m models/qwen2.5-7b-instruct.Q4_K_M.gguf `
  -ngl 99 `
  --device Vulkan0 `
  -t 8 `
  --ctx-size 4096 `
  -p "写一份500字的端午节活动策划方案，面向公司员工" `
  -n 1024 `
  --temp 0.6 `
  -o 活动方案.txt
```
关键参数：
- `-p "xxx"`：指定输入的提示词（prompt）
- `-n 1024`：最大生成token数，控制输出长度
- `-o 活动方案.txt`：将生成的内容自动保存到指定文件

#### （3）高级定制用法
- 从文件读取prompt：把长提示词写到txt文件中，避免命令行过长
  ```powershell
  .\llama-cli.exe -m 模型路径 -f prompt.txt -n 2048
  ```
- 强制结构化输出：用`--grammar`参数通过BNF语法约束输出格式，比如强制输出JSON
  ```powershell
  # 强制输出JSON格式的用户信息
  .\llama-cli.exe -m 模型路径 -p "生成一个用户信息，包含姓名、年龄、职业" --grammar 'root ::= "{" "name": "\"" [a-zA-Z]+ "\"" ", " "age": [0-9]+ ", " "job": "\"" [a-zA-Z]+ "\"" "}"' -n 128
  ```
- 多轮对话状态保存：保存对话上下文，下次启动直接恢复
  ```powershell
  # 保存对话状态
  .\llama-cli.exe -m 模型路径 -i --save-session chat.session
  # 恢复对话状态
  .\llama-cli.exe -m 模型路径 -i --load-session chat.session
  ```

### 场景2：OpenAI兼容API服务（llama-server）
这是llama.cpp最具扩展性的功能，启动后可对接几乎所有支持OpenAI API的应用，比如ChatGPT-Next-Web、Obsidian、Python脚本、LangChain等。

#### （1）基础服务启动命令（适配860M核显）
```powershell
.\llama-server.exe `
  -m models/qwen2.5-7b-instruct.Q4_K_M.gguf `
  -ngl 99 `
  --device Vulkan0 `
  -t 8 `
  --ctx-size 4096 `
  --flash-attn `
  --chat-template auto `
  -p 8080 `
  --host 0.0.0.0 `
  --cors * `
  --api-key your_custom_key
```
核心参数说明：
- `-p 8080`：服务监听端口，可自定义
- `--host 0.0.0.0`：允许局域网内其他设备访问（比如手机、其他电脑）
- `--cors *`：解决跨域问题，对接前端应用必加
- `--api-key your_custom_key`：设置API密钥，防止未授权访问，可选

#### （2）核心功能使用
1.  **自带Web聊天界面**
    启动服务后，浏览器访问 `http://localhost:8080` 即可直接使用可视化聊天界面，支持多轮对话、参数调整、文件上传等功能。

2.  **OpenAI API兼容调用**
    完全兼容OpenAI的API格式，仅需把接口地址中的 `https://api.openai.com/v1` 替换为 `http://localhost:8080/v1` 即可。
    - 核心端点：
      - 聊天补全：`POST http://localhost:8080/v1/chat/completions`
      - 文本补全：`POST http://localhost:8080/v1/completions`
      - 模型列表：`GET http://localhost:8080/v1/models`
      - 嵌入生成：`POST http://localhost:8080/v1/embeddings`
    - Python调用示例（使用openai库）：
      ```python
      from openai import OpenAI

      # 初始化客户端，指向本地llama.cpp服务
      client = OpenAI(
          base_url="http://localhost:8080/v1",
          api_key="your_custom_key" # 与启动命令中的api-key一致
      )

      # 调用聊天接口
      response = client.chat.completions.create(
          model="qwen2.5-7b",
          messages=[{"role": "user", "content": "你好，介绍一下llama.cpp"}],
          temperature=0.7,
          max_tokens=512
      )

      print(response.choices[0].message.content)
      ```

3.  **高级服务优化**
    - 并发优化：开启持续批处理，提升多用户并发能力
      ```powershell
      # 新增参数：--cont-batching 开启持续批处理，--parallel 4 最大并行请求数
      .\llama-server.exe -m 模型路径 --cont-batching --parallel 4
      ```
    - 多模型同时加载：启动时指定多个模型，API调用时可切换
      ```powershell
      .\llama-server.exe --model 模型1路径 --model 模型2路径 --model 模型3路径
      ```
    - 配置文件启动：把所有参数写到yaml配置文件中，避免命令行过长
      ```powershell
      .\llama-server.exe --config config.yaml
      ```

### 场景3：GGUF模型处理（llama-gguf）
用于自定义处理模型，解决模型下载后信息不明确、需要量化、合并LoRA等需求。

#### （1）查看模型详细信息
```powershell
.\llama-gguf info models/qwen2.5-7b-instruct.Q4_K_M.gguf
```
可查看模型的参数大小、层数、上下文窗口、量化等级、分词器、支持的功能等核心信息，避免下错模型。

#### （2）模型量化（自定义生成低比特GGUF）
如果下载了FP16/FP32的高版本模型，可自行量化为适配你硬件的低比特版本：
```powershell
# 把FP16模型量化为Q4_K_M格式
.\llama-gguf quantize `
  models/qwen2.5-7b-instruct.FP16.gguf `
  models/qwen2.5-7b-instruct.Q4_K_M.gguf `
  Q4_K_M
```
量化等级可替换为 `Q2_K`、`Q5_K_M`、`Q8_0` 等。

#### （3）LoRA适配器融合
把微调后的LoRA模型合并到基础GGUF模型中，生成可直接推理的完整模型：
```powershell
.\llama-gguf merge-lora `
  --base-model 基础模型路径.gguf `
  --lora-path lora适配器路径.gguf `
  --output 合并后的完整模型.gguf
```

### 场景4：性能基准测试（llama-bench）
测试你的硬件在不同参数下的性能，找到最优配置：
```powershell
# 适配860M核显的基准测试命令
.\llama-bench.exe `
  -m models/qwen2.5-7b-instruct.Q4_K_M.gguf `
  -ngl 99 `
  --device Vulkan0 `
  -t 8 `
  -c 4096 `
  -b 512
```
测试完成后会输出**prompt处理速度**、**token生成速度**、**内存/显存占用**等核心数据，可用于调整线程数、GPU层数等参数，找到最优配置。

## 四、AMD Radeon 860M 专属性能优化指南

### 1. 硬件层面优化
1.  **更新最新AMD Adrenalin驱动**：必须从AMD官网下载官方驱动，不要使用Windows更新的通用驱动，新版驱动对Vulkan有大幅优化，提升推理速度30%以上。
2.  **电源模式设置**：Windows设置→系统→电源和电池，设置为**最佳性能**；AMD Adrenalin驱动中，把显卡电源设置为**最高性能**。
3.  **显存优化**：BIOS中开启Resizable BAR（如果支持），Windows中关闭核显显存限制，让核显能调用更多系统内存作为显存。

### 2. 软件层面优化
1.  **线程优化**：`-t` 固定为8（你的CPU物理核心数），不要设置为16（超线程数），llama.cpp对超线程优化极差，反而会降低速度。
2.  **GPU层优化**：7B模型固定`-ngl 99`，全部层加载到核显；14B模型可设置`-ngl 30`，部分层加载到GPU，平衡速度与显存占用。
3.  **上下文窗口控制**：日常使用`--ctx-size 4096`完全足够，不要盲目开到8192/16384，会大幅增加显存占用，降低生成速度。
4.  **后台程序清理**：关闭浏览器、视频播放器、游戏等占用显存/内存的程序，避免资源抢占导致推理速度下降。

### 3. 模型选择优化
- 日常使用：优先7B参数Q4_K_M量化模型，生成速度15-20 token/s，完全满足日常对话需求。
- 复杂任务：14B参数Q4_K_M量化模型，生成速度8-12 token/s，推理能力大幅提升，你的32GB内存完全可运行。
- 极速响应：3B/1B参数模型，生成速度30-40 token/s，适合简单问答、快速信息查询。

## 华硕无畏Pro16 锐龙版（Ryzen AI7 H350 + Radeon 860M）显存调整说明

> 
> 重点区分：**UMA 预分配显存（BIOS设置的最小预留显存） ≠ 最大共享显存上限**
> Windows系统默认是动态共享，860M会按需自动拿内存，BIOS调的只是**最低预留固定显存**，不是把内存永久全部划给显卡。

### ✅ 两种调整方法（优先MyASUS软件，不用进BIOS）

**方式1：MyASUS 软件调整（华硕新机型推荐，最简单）**

1. 安装【MyASUS】华硕管家
2. 打开 → 设备设定 → 一般 → 电池与效能
3. **分配内存给GPU**，选择大小，重启生效> 
> 这个就是AMD UMA Frame Buffer，也就是预分配显存

**方式2：BIOS内调整（F2进入）**

1. 电脑完全关机，开机看到华硕logo时**连续按F2**进入BIOS
2. 进入 `Advanced` 高级选项 → 找到 `UMA Frame Buffer Size`（UMA帧缓冲，就是预分配显存）
3. 修改数值，F10保存重启> 
> ⚠️ 部分新版华硕无畏Pro16的BIOS可能锁死该选项，只能用MyASUS修改

### 📊 针对你跑 llama.cpp 的推荐设置（核心）

> 
> 前提：看你机器是**16GB板载内存 还是32GB**
> 
> 
> | 本机内存 | 推荐UMA预分配 | 适合场景 | 利弊 |
> | --- | --- | --- | --- |
> | 16GB（板载） | 4GB | 跑14B模型（Q4_K_M） | ✅给860M基础预留，方便-ngl卸载更多层   ❌固定扣走4G，Windows系统可用内存变少，**不建议调到8G**，极易OOM |
> | 32GB（板载LPDDR5X） | 6GB~8GB | 跑27B Q4模型 | ✅跑27B模型，GPU可以hold更多层，减少CPU交换   ✅剩余内存充足，系统不会卡顿 |

### ❗非常关键：对llama.cpp的误区澄清

1. **调高UMA不是凭空多出显存**
860M本身就是共享内存架构，Windows默认动态机制：显卡需要多少，系统就动态划拨。BIOS/MyASUS设置的只是**最低保底预留**。
哪怕UMA只设1GB，在内存充足时，860M依然可以动态吃到十几GB内存。
2. **什么时候才值得调大？**
你在llama.cpp启动报Vulkan显存分配失败、无法把模型层卸载到GPU（`-ngl`参数加载报错），这种情况**才需要上调UMA**；
如果现在模型可以正常加载，**完全没必要修改**，维持默认即可。
3. **盲目调大的坏处**
UMA设置的值，开机就**永久锁定划走这部分内存给显卡**，哪怕显卡闲置，Windows和llama也用不到这块内存。
16G内存机型如果UMA设8G，系统仅剩8G可用，Windows+llama很容易爆内存、蓝屏、swap疯狂读写，推理速度暴跌。

### 🎯 给你的实操建议（结合你之前llama-server参数）

1. 如果你的笔记本是**16G内存版本**
   - UMA设置：4GB，不要更大；
   - llama参数沿用：14B模型 `-ngl 35`，27B模型 `-ngl 20`，`--flash-attn on -ctk q4_0`；
   - 27B模型尽量少开其他软件，释放系统内存。
2. 如果是**32G内存版本**
   - UMA可以设置 6GB~8GB；
   - 可以尝试把27B的 `-ngl` 小幅提高（20→24），看能否多卸载几层，观察是否OOM。

## 补充检查方法

修改完成重启后，Win+R输入 `dxdiag`，切换到【显示】页面，查看**专用显存**就是UMA预分配大小；共享显存是系统动态可用上限。

你可以告诉我你的笔记本总内存是16GB还是32GB，我帮你确定最合适的UMA值，顺带微调llama-server启动参数。

## 五、常见问题排查与解决方案
### 1. 模型加载失败/内存不足
- 解决方案：降低模型量化等级（如Q4_K_M换成Q2_K）；减小`--ctx-size`；降低`-ngl`的数值，减少加载到GPU的层数；关闭其他占用内存的程序。

### 2. Vulkan设备找不到/核显不生效
- 解决方案：更新AMD官方显卡驱动；重启电脑；把`--device Vulkan0`改为`--device Vulkan1`；确认下载的是`Windows x64 (Vulkan)`版本的安装包，不是CPU/CUDA版本。

### 3. 生成速度极慢/跑在CPU上
- 解决方案：确认启动命令加了`-ngl 99 --device Vulkan0`；查看启动日志，确认`Vulkan`设备已被调用；更新显卡驱动；调整`-t`参数为物理核心数。

### 4. 输出乱码/胡言乱语/重复
- 解决方案：添加`--chat-template auto`参数，适配模型的对话模板；添加`--encoding utf-8`解决中文乱码；调整`--repeat-penalty 1.1`降低重复；确认下载的是`Instruct`/`Chat`对话模型，不是基础预训练模型。

### 5. API服务无法被局域网访问
- 解决方案：启动命令加`--host 0.0.0.0`；Windows防火墙放行对应的端口（如8080）；关闭VPN/代理软件；确认局域网内设备在同一网段。
