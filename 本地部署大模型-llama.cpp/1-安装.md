# 主流大模型部署工具对比表
> 已包含：llama.cpp、Ollama、LM‑Studio，同时补充业界常用工具；**联系说明**：Ollama、LM‑Studio底层均复用llama.cpp推理内核；vLLM/SGLang/TensorRT‑LLM属于GPU生产级推理引擎；Text‑Generation‑WebUI、OpenWebUI属于上层交互界面，可对接多种推理后端。

|工具名称|底层内核|主要形态|支持模型格式|支持硬件|核心优势|主要短板|适用场景|
|---|---|---|---|---|---|---|---|
|**llama.cpp**|自研C/C++推理引擎|命令行库/CLI，无自带GUI|GGUF、GGML|CPU、NVIDIA、AMD、Apple Metal、Vulkan，跨平台极强|轻量、量化支持最全；低配CPU/内存可跑；可深度调参；可嵌入式集成|无UI；并发能力弱；需要手动管理模型文件|边缘设备、嵌入式、深度调参、低硬件资源本地推理|
|**Ollama**|llama.cpp|CLI+OpenAI兼容API服务|GGUF|Windows/macOS/Linux，CPU/GPU/M‑Series|一键拉取运行模型；自动硬件适配；Modelfile自定义模型；开箱即用API；生态丰富|并发性能一般；对llama.cpp上游新特性更新滞后；不适合大规模多用户生产|个人本地开发、原型调试、本地API服务、RAG后端|

|**vLLM**|自研CUDA推理引擎(PagedAttention)|命令行/API服务|GPTQ、AWQ、FP8、FP16|Linux；NVIDIA、AMD ROCm；**不支持macOS**|工业级高吞吐；连续批处理；多GPU张量并行；新模型适配快；社区庞大|不支持macOS；本身显存开销大；CPU推理弱|云端/服务器多用户生产API、企业推理服务、批量推理任务|
|**SGLang**|自研(RadixAttention)|命令行/API服务|GPTQ、AWQ、FP8|Linux；NVIDIA、AMD、昇腾、TPU|前缀缓存优化（Agent/RAG收益巨大）；结构化JSON输出性能强；支持多LoRA、推测解码|社区规模略小于vLLM；部分新模型适配稍慢|Agent工作流、RAG、需要强制结构化输出、多轮长对话服务|
|**TensorRT‑LLM**|NVIDIA TensorRT算子编译|库+服务封装|FP8、INT4、INT8|仅NVIDIA GPU（Linux/Windows）|N卡硬件性能天花板；延迟、吞吐最优；支持多机多卡并行|模型需要编译，编译耗时长；仅支持NVIDIA；灵活性差|NVIDIA集群极致性能生产部署，流量极大的线上服务|
|**MLX‑LM**|Apple MLX框架|Python库/CLI|MLX格式|**仅Apple Silicon(M系列芯片)**|苹果芯片原生加速；支持推理+微调；内存优化优秀|仅限macOS；模型格式为MLX专用，不兼容GGUF|Mac平台本地推理、小模型本地微调开发|
|**LMDeploy**|TurboMind引擎|命令行/API/WebUI|GPTQ/AWQ/INT4|NVIDIA、国产昇腾NPU|国产硬件适配优秀；低首包延迟；支持多模态；轻量化选项|海外社区相对小；部分小众模型适配慢|国产算力服务器、多模态模型部署、边缘GPU服务|
|**Text‑Generation‑WebUI**|可对接llama.cpp/vLLM/exllama等多后端|Web网页UI|GGUF/GPTQ/AWQ等|全平台，取决于后端|插件生态极丰富；采样参数最全；扩展能力强|配置复杂；资源占用高；后端需要额外部署|本地研究、模型调参实验、玩各种采样/扩展插件|
|**Aphrodite‑Engine**|vLLM二次fork|API服务|GGUF/GPTQ/AWQ/AQLM等超多量化格式|Linux NVIDIA|支持市面几乎全部量化格式；增加角色向采样算法|AGPL协议；基于vLLM二次开发，稳定性略弱于原版vLLM|创意写作、角色扮演、需要多种冷门量化格式场景|
|**LocalAI**|可对接llama.cpp等多后端|Docker容器API服务|GGUF等|全平台Docker部署|OpenAI完全兼容；支持LLM、Embedding、图像、语音多模态|性能上限取决于后端引擎；配置项较多|私有化完整OpenAI兼容服务，容器化快速部署|

## 工具层级关系（联系）
1. **底层推理内核**：llama.cpp、vLLM、SGLang、TensorRT‑LLM、MLX、TurboMind；负责张量计算、KV缓存、量化解码。
2. **模型管理/封装层**：Ollama（封装llama.cpp）、LocalAI；在内核之上做模型下载、硬件识别、API封装。
3. **上层UI交互层**：LM‑Studio、Text‑Generation‑WebUI、Open‑WebUI；本身**不做推理**，对接上面任意推理后端，提供聊天界面。

## 快速选型口诀
- 个人电脑（Windows/Mac）简单玩：**Ollama（开发API） / LM‑Studio（GUI点鼠标）**
- 低配CPU/内存跑模型：**llama.cpp**
- Linux服务器多用户线上服务：**vLLM**
- Agent/RAG大量重复System‑Prompt：**SGLang**
- Mac M系列追求原生速度：**MLX‑LM**
- NVIDIA集群压榨极限性能：**TensorRT‑LLM**
- 国产昇腾硬件：**LMDeploy**

# llama.cpp 最新安装与配置指南（全平台通用）
涵盖**预编译二进制、Python绑定、源码编译、Docker**四种核心安装方式，支持 Windows / macOS / Linux 全平台，包含 GPU 加速、模型运行、参数配置、常见问题完整解决方案。

## 一、安装方式选择
| 安装方式 | 难度 | 适用场景 |
|---------|------|---------|
| 预编译二进制 | ⭐ 最简单 | 快速体验，无需编译环境，开箱即用 |
| Python 绑定 | ⭐⭐ 简单 | Python 开发者，快速集成到项目中 |
| 从源码编译 | ⭐⭐⭐ 进阶 | 需要 GPU 加速、自定义优化、最新功能 |
| Docker | ⭐⭐ 简单 | 跨平台部署、环境隔离、一键启动服务 |
| 包管理器 | ⭐ 最简单 | macOS(Homebrew)、Linux(Nix) 一键安装 |

## 二、方式一：预编译二进制（新手首选）
无需编译、无需依赖，解压即可运行。
1. 下载：前往 [llama.cpp GitHub Releases](https://github.com/ggerganov/llama.cpp/releases)，下载对应系统的压缩包
2. 解压并进入目录，执行命令：
```bash
# 启动 Web UI 服务（推荐）
./llama-server -m ./your-model.gguf -c 4096 --port 8080

# 交互式命令行对话
./llama-cli -m ./your-model.gguf -p "你好" -n 256
```
3. 访问 `http://localhost:8080` 即可使用内置 Web 界面。

## 三、方式二：Python 绑定（llama-cpp-python）
适合 Python 开发场景，支持 CPU/GPU 模式。
### 1. 基础安装（CPU 模式）
```bash
pip install llama-cpp-python
```

### 2. GPU 加速安装
- **NVIDIA GPU (CUDA)**
```bash
CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --upgrade --force-reinstall
```
- **Apple Silicon (Metal，M1/M2/M3/M4)**
```bash
CMAKE_ARGS="-DGGML_METAL=on" pip install llama-cpp-python --upgrade --force-reinstall
```

### 3. Python 代码示例
```python
from llama_cpp import Llama

# 加载模型（-1 表示全部层卸载到 GPU）
llm = Llama(
    model_path="./qwen2.5-7b-instruct-q4_k_m.gguf",
    n_ctx=4096,
    n_gpu_layers=-1
)

# 生成对话
output = llm("你好，请介绍 llama.cpp 的特色", max_tokens=256)
print(output['choices'][0]['text'])
```

### 4. 启动 OpenAI 兼容 API 服务
```bash
pip install 'llama-cpp-python[server]'
python3 -m llama_cpp.server --model models/7B/llama-model.gguf --n_gpu_layers 35
```
访问 `http://localhost:8000/docs` 查看可视化 API 文档。

## 四、方式三：从源码编译（进阶/性能最优）
### macOS
```bash
# 1. 安装依赖
xcode-select --install
brew install git cmake

# 2. 克隆仓库
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

# 3. 编译（Apple Silicon 启用 Metal 加速）
cmake -B build -DGGML_METAL=ON
cmake --build build --config Release

# 4. 验证安装
./build/bin/llama-cli --help
```
✅ 一键安装：`brew install llama.cpp`

### Linux (Ubuntu/Debian)
```bash
# 1. 安装依赖
sudo apt update
sudo apt install -y git build-essential cmake

# 2. 克隆仓库
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

# 3. 编译
# CPU 模式
cmake -B build
cmake --build build --config Release -j $(nproc)

# NVIDIA GPU 加速模式
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release -j $(nproc)
```

### Windows
#### 选项 A：Visual Studio（推荐）
1. 安装 Visual Studio，勾选 **C++ 桌面开发**
2. 安装 Git + CMake
3. 编译命令：
```powershell
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

mkdir build
cd build
cmake ..
cmake --build . --config Release
```

#### 选项 B：WSL（Linux 子系统）
```powershell
wsl --install  # 安装 WSL
# 后续按照 Linux 编译步骤执行
```

#### 选项 C：MSYS2（高级用户）
```bash
pacman -Syu
pacman -S mingw-w64-x86_64-gcc cmake git
# 克隆仓库后执行编译
```

## 五、方式四：Docker 部署（跨平台/隔离环境）
```bash
# 拉取镜像
docker pull ghcr.io/ggerganov/llama.cpp:latest

# 启动服务（挂载模型目录）
docker run --rm -it -p 8080:8080 \
  -v /path/to/models:/models \
  ghcr.io/ggerganov/llama.cpp:latest \
  --model /models/llama-model.gguf --port 8080
```

### 总结
1. 新手优先选择**预编译二进制**，开箱即用；Python 开发者直接用 `llama-cpp-python`
2. 追求性能选择**源码编译**，开启对应硬件的 GPU 加速（CUDA/Metal/Vulkan）
3. 模型必须使用 **GGUF 格式**，推荐 Q4_K_M 量化版本平衡速度与效果
4. 核心命令：`llama-server` 启动 Web 服务，`llama-cli` 命令行对话
